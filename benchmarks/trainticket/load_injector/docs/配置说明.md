# 配置说明

混合配置文件位于 `configs/mix/`。

当前提供四个示例：

- `steady.yaml`：恒定负载
- `step.yaml`：阶梯负载
- `burst.yaml`：突发负载
- `smoke.yaml`：最小功能验证

## 顶层字段

- `name`：配置名
- `description`：配置说明
- `phases`：阶段列表

## `phase` 字段

- `name`：阶段名
- `duration_min`：阶段持续时间，单位分钟
- `users`：该阶段用户数
- `spawn_rate`：用户增长速度
- `arrival_rate`：预留字段，当前版本暂未作为主调度参数使用
- `mix`：场景比例

## `mix` 约束

- `mix` 的 key 必须是注册表中存在的场景 ID
- `mix` 的 value 为相对权重，不要求总和必须等于 1
- 运行时会自动归一化

例如：

```yaml
name: steady
description: 恒定负载示例

phases:
  - name: steady-20m
    duration_min: 20
    users: 20
    spawn_rate: 5
    mix:
      browseBasic: 0.24
      browseAdvanced: 0.08
      orderRefresh: 0.10
      preserveAndPay: 0.14
      preserveWithFood: 0.05
      preserveWithAssurance: 0.05
```

## 配置建议

- 浏览类和支撑类通常应占较大比例，用来构成稳定背景流量
- 交易类场景建议维持中低比例，避免状态依赖场景过多影响稳定性
- 后台观察类通常保持低比例即可
- 若要做稳定训练数据，建议先用 `steady.yaml` 或小规模 `step.yaml`
- 若要验证新增场景是否能跑通，优先使用 `smoke.yaml` 或单场景 dry-run

## 推荐分层

- 浏览类：`browseBasic`、`browsePlusRoute`、`browseAdvanced`、`browseAdvancedAlt`
- 支撑类：`orderRefresh`、`contactLookup`、`foodBrowseOnly`、`postPurchaseOrderView`
- 交易类：`preserveAndPay`、`preserveWithFood`、`preserveWithAssurance`、`payCollectEnter`、`cancelFlow`、`rebookFlow`、`consignFlow`
- 观察类：`adminObserve`
